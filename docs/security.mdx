`teaway` changes macOS power behavior only after an explicit command. It has no network listener, cloud service, telemetry, workload inspection, password cache, setuid executable, or always-running daemon.

It **never reads, stores, logs, or pipes an administrator password**. When macOS presents an authentication dialog, that exchange belongs to macOS. Privileged operations use fixed system paths (`/usr/bin/pmset`), never an arbitrary shell.

Read-only commands — `teaway status` and `teaway version` — do not modify power settings or scheduled events.

## Ownership

`on` snapshots the current sleep setting, applies `disablesleep=1`, and reports success only after verification. `off` restores only that owned snapshot. A live `disablesleep=1` value with no teaway record is left alone.

Shutdown scheduling is independent of awake mode. Durations are bounded (10 minutes to 7 days). Cancellation removes only the exact teaway-owned event — never `pmset cancelall`.

## Registered helper

`teaway auth register` (also offered by the client) installs two root-owned, per-user files after one visible administrator authorization:

- `/Library/PrivilegedHelperTools/com.soundadam.teaway.helper.<uid>`
- `/etc/sudoers.d/soundadam-teaway-<uid>`

The rule permits only `disablesleep` `0`/`1`, one canonical shutdown schedule, exact cancellation of a matching event, and helper version inspection. It does not permit the public CLI, a shell, or arbitrary `pmset` arguments.

<Warning>
  The sudoers rule trusts the entire macOS user account. Any process running as that user can invoke the allowlisted operations. Do not register the helper on a shared or untrusted account.
</Warning>

A version mismatch between the helper and the current binary fails closed. The client offers repair; it will not replace a root-owned helper during `brew upgrade`.

## Supply chain

The repository, Homebrew token, Go module, and executable are all `teaway`. Homebrew verifies the source-archive SHA-256 and builds on the machine. Public releases do not ship unnotarized prebuilt executables.

## Vulnerability reporting

Do **not** file a public GitHub issue for a suspected vulnerability. Use GitHub's **Report a vulnerability** form in the repository Security tab. Full instructions are in [SECURITY.md](https://github.com/soundadam/teaway/blob/main/SECURITY.md).
