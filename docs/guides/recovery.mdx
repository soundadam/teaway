teaway records ownership of every change it makes and uses that record to reverse changes precisely. When an operation is interrupted, a conflicting external state is detected, or a stored record no longer matches what macOS reports, teaway surfaces a named recovery state rather than silently inventing success or making a destructive guess. This guide walks through each state and the correct resolution path.

## Start with read-only inspection

Before taking any corrective action, run the three read-only status commands to understand what teaway sees:

```sh
teaway status
teaway shutdown status
teaway auth status
```

These commands never modify power settings or scheduled events. Interpret the output before deciding what action to take.

<Warning>
  Do not delete teaway state files manually. teaway uses those files to reverse only the exact change it made. Removing them destroys the information needed for a safe `teaway off` or `teaway shutdown cancel`, and can leave macOS in a state that teaway can no longer recover cleanly.
</Warning>

## needs-recovery

`teaway status` reports `needs-recovery` when a transaction journal remains after an operation that was interrupted or could not be fully verified. This means teaway started a change, could not confirm the outcome, and preserved the partial record rather than guessing.

**Resolution:**

1. Run the matching command to resolve the owned transition:
   ```sh
   teaway off
   ```
   Or, if the recovery state relates to a shutdown:
   ```sh
   teaway shutdown cancel
   ```
2. Re-check macOS state after the command completes:
   ```sh
   teaway status
   teaway shutdown status
   ```

teaway works through the journal to reverse the owned change and verify the resulting macOS state. If the command reports success, the recovery is complete. If it reports a further error, re-read the output carefully — it will name the specific condition and what is needed.

## external awake state

`teaway status` reports `external` when `disablesleep=1` is live in macOS but teaway has no ownership record for that value. Another tool, a system administrator, or a manual `pmset` command set it.

`teaway off` deliberately leaves an external value unchanged. Because teaway did not set it, teaway does not own it, and clearing it could silently undo policy that belongs to something else.

**Resolution:**

Use `/usr/bin/pmset -g` to inspect the live macOS state without modifying it:

```sh
/usr/bin/pmset -g
```

Decide which tool owns the `disablesleep` setting and use that tool to clear it. Once the external value is cleared and `teaway status` reports `disablesleep=0` with no teaway ownership, you can use `teaway on` to take ownership from a clean baseline.

<Info>
  `/usr/bin/pmset -g` is a safe, read-only inspection command. It reports current power settings without changing anything.
</Info>

## needs-repair (auth)

`teaway auth status` reports `needs-repair` when the registered helper/sudoers rule pair is incomplete, unauthorized, or version-mismatched. This most commonly happens after a teaway upgrade, but can also occur if one of the two installed files was removed or altered outside of teaway.

**Resolution:**

Re-run registration to replace both files with a matching pair:

```sh
teaway auth register
teaway auth status
```

If you prefer to remove registered mode entirely and return to ordinary sudo:

```sh
teaway auth unregister
teaway auth status
```

Both commands use visible administrator authorization. See the [Authorization guide](/guides/authorization) for a full explanation of what the helper installs and permits.

## Stale shutdown record

`teaway shutdown status` reports a stale record when teaway's stored shutdown record refers to an event that macOS no longer reports in its schedule. This can happen if macOS already executed the shutdown, if the event was cancelled outside of teaway, or if the system was restarted.

`teaway shutdown status` detects this condition automatically and clears the stale record when it runs. You do not need to take additional action to clear it.

**Resolution:**

```sh
teaway shutdown status
```

After the stale entry is cleared, you can schedule a new shutdown normally:

```sh
teaway shutdown after 2h
```

## Emergency read-only inspection

If you are uncertain about the current macOS power state, use these two read-only commands directly. They bypass teaway entirely and report what macOS currently holds:

```sh
/usr/bin/pmset -g
/usr/bin/pmset -g sched
```

`pmset -g` shows current power settings including `disablesleep`. `pmset -g sched` lists all scheduled power events, including any teaway-owned shutdown.

<Warning>
  Avoid broad pmset cancellation commands such as `pmset cancelall`. These commands remove every scheduled power event on the system — including wake events owned by macOS itself, iCloud, or other applications — and cannot be easily undone. Use `teaway shutdown cancel` to remove only the teaway-owned event, or remove nothing until you understand exactly what is scheduled.
</Warning>
