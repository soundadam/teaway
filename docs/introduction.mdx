teaway is a focused macOS command-line tool that keeps a Mac working when normal sleep would interrupt it — including a MacBook with the lid closed — then restores the exact power setting it owned before you ran `teaway on`. It is designed for operators who want a clear, auditable power contract with no background control plane in the way.

## What teaway does

teaway manages the macOS `disablesleep` power setting on your behalf. When you run `teaway on`, it snapshots the current sleep state, applies `disablesleep=1`, verifies the change, and records ownership. When you run `teaway off`, it reads that ownership record and restores only the value it saved — if no record exists, it does nothing, so it can never silently undo a setting owned by something else.

teaway also lets you schedule a single, precisely owned shutdown with an explicit duration (for example `teaway shutdown after 2h`), inspect and cancel only that shutdown, and manage authorization through an optional narrow helper that removes repeated password prompts without granting a shell or arbitrary `pmset` access.

## Primary use cases

- **Spare MacBook build box.** Keep a closed-lid MacBook available as a CI runner or compilation host without a full server OS.
- **Mac mini home server.** Run self-hosted services — a media server, a code repository, a home automation hub — that must survive the end of your interactive session.
- **Homelab node.** Integrate a Mac into a broader homelab alongside Linux machines, keeping power control explicit and reversible.
- **Long backups and media jobs.** Prevent the Mac from sleeping mid-job without leaving a process running in the foreground.

## How teaway differs from other approaches

Most tools that prevent sleep work by keeping a foreground process alive. teaway manages the `disablesleep` state directly, which means the Mac stays awake even when the lid is closed and no user session is active. Ownership is recorded so that `teaway off` restores only what `teaway` changed — it will not clear a setting that was already `1` before teaway ran.

Registration installs a root-owned, per-user helper with a narrow sudoers rule. That rule permits only the exact `disablesleep` values `0` and `1`, one canonical teaway shutdown schedule, and exact cancellation of a matching event. It does not permit arbitrary CLI commands, arbitrary `pmset` arguments, or a shell.

There is no daemon, no background listener, no account, no telemetry, and no cloud dependency of any kind.

## Requirements

<Info>
  teaway requires **macOS 13 Ventura or later** running on Apple Silicon or an Intel Mac supported by that macOS release. Administrator authorization is required for power mutations and helper registration.
</Info>

## What teaway does not do

teaway manages the power lifecycle only. It deliberately does not configure or supervise:

- Remote Login (SSH) or Screen Sharing
- VPNs, firewalls, or DNS
- Network interfaces or Wi-Fi settings
- launchd services or other service supervisors
- Backups, monitoring, or storage health
- Any workload running on the machine

These responsibilities belong to the rest of your availability stack. teaway is one focused layer in that stack, not a replacement for it.
