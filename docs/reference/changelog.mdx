teaway follows a deliberate, minimal release cadence — each version either tightens safety boundaries, improves the user experience, or both. This page documents every notable change from the user's perspective. The most recent releases are shown in full; older releases are folded into expandable sections to keep the page scannable.

---

## Unreleased

These changes are in the main branch and will ship in the next release.

### Fixed

- The guided menu now draws on an alternate screen buffer, so the action prompt is no longer painted twice and leftover status-box border characters no longer persist after a `state.json` ownership repair.

### Changed

- **The TUI is now a session client.** It stays open after you complete an action, so you can run multiple operations — `on`, `shutdown after`, `status` — without re-launching teaway. The separate Refresh command has been removed; the view updates after each action.
- **`teaway` with no arguments is now the canonical entry point** for interactive use. `teaway tui` and `teaway interactive` are deprecated; they still work but will be removed in a future release.
- teaway no longer reads `TEA_STATE_DIR`, `TEA_AWAY_STATE_DIR`, or sibling `tea-away` state files. Legacy `tea-away:` shutdown events remain cancellable for migration purposes.
- When a privileged action requires passwordless controls, teaway now prompts you to set them up or repair them immediately — before the action — rather than falling back to a bare `sudo` prompt.
- The shutdown duration input has been replaced with a stepped picker covering 10 minutes to 7 days, with a custom-duration fallback for precise values.
- The original Swift CLI has been replaced with a Go command tree (Cobra) and a Charm TUI (`huh` + `lipgloss`). Running `teaway` with no arguments now opens a guided interactive menu rather than a numbered prompt.
- teaway now refuses to run the user-facing CLI as root and explains how to reclaim a `state.json` that became unreadable after an accidental `sudo teaway`.

## 0.4.2 — 2026-08-19

### Changed

- **`teaway on` now works on battery power without any restriction.** In earlier versions, battery power could block or warn during `on`. Now the decision is yours — teaway applies the same behavior on battery or AC. `teaway status` still reports the current power source so you can see what you're running on.

---

## 0.4.1 — 2026-08-05

### Changed

- **Passwordless helper setup is now discoverable from the guided menu.** If you haven't registered the helper yet, teaway surfaces the option at the right moment — right before you would otherwise be prompted by macOS. Before invoking `sudo`, it explains that the one-time password entry is hidden, used once, and never read or stored by teaway.

---

## 0.4.0 — 2026-08-05

### Changed

- **Status and action output is now more approachable.** Plain-language explanations accompany native power values, so you can understand what teaway did without reading pmset documentation.
- **`teaway interactive` (and `teaway tui`) introduced a guided menu** over the same bounded power and shutdown operations. The menu exited after completing one action in this release. (In Unreleased, it now stays open as a session client.)
- **Running `teaway` with no arguments now opens the guided menu** instead of printing help text. `teaway status` remains available as a direct, non-interactive status command.
- The repeated remote-reachability warning that appeared on `teaway on` has been removed. Reachability is an operator preflight step, documented in the operating guide, not a runtime gate.
- The long typed confirmation previously required to schedule a shutdown has been removed. The explicit bounded `teaway shutdown after <duration>` command now schedules directly and still verifies the exact macOS event before confirming.

### Fixed

- Stale shutdown journal entries — where macOS no longer reports the owned event — are now reconciled and cleared automatically. They no longer block a subsequent `teaway shutdown after`.

<Accordion title="0.3.0 — 2026-07-26">

### Added

- **Optional passwordless helper**: `teaway auth register`, `teaway auth status`, and `teaway auth unregister` commands install and manage a narrow, root-owned per-user sudoers rule. Once registered, privileged operations no longer prompt for a password.
- macOS 26 scheduled-power-event parsing, including normalization of two-digit and four-digit year rendering differences in pmset output.
- New documentation covering server-oriented operations, authorization model, security model, migration from legacy scripts, and release readiness.

### Changed

- teaway is now positioned and documented for headless, homelab, self-hosted, and long-running Mac operation.
- Ordinary privileged operations preserve the existing sudo credential cache rather than forcing a new authentication prompt.
- Shutdown verification and cancellation compare a canonical exact tuple, so they remain correct even when macOS changes how it displays the year in pmset output.

### Security

- The registered helper mode delegates only the fixed sleep operations and exact shutdown cancellation. It does not grant arbitrary `pmset` arguments, access to the public CLI, or shell execution.
- Stale or partial helper installations fail closed — teaway will not proceed with a version-mismatched helper.

</Accordion>

<Accordion title="0.2.3 — 2026-07-26">

- teaway no longer creates a legacy state directory on disk when that directory is absent and only the default lock path is checked.
- `soundadam` is now formalized as the publisher identity, and `teaway` is the canonical repository name, Homebrew Formula token, and executable name.

</Accordion>
