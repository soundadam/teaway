If you previously used a personal shell implementation called `tea` or `tea-away` to manage Mac sleep, this page walks you through a clean handoff to teaway. Follow it in order to avoid leaving orphaned power state or stranded shutdown events on your machine.

<Note>
  This page applies **only** to machines that previously ran the retired personal shell implementation. If teaway is your first install, skip this page entirely — there is nothing to migrate.
</Note>

## Before you repoint any alias

Do not reassign your `tea` shell alias to `teaway` until the legacy tool has cleaned up its own state. The two implementations use separate state stores, and teaway will not import, rewrite, or touch legacy files.

**First**, use the original implementation by its full path to check and restore its state:

```sh
/path/to/legacy/tea status
/path/to/legacy/tea off
```

This ensures the legacy tool reverses any `disablesleep` setting it owns before you hand control to teaway. If `tea off` fails or the path is no longer available, check the legacy state directory manually and use `sudo pmset -a disablesleep 0` to clear the value if needed.

**Then**, inspect the native baseline with teaway to confirm a clean starting point:

```sh
teaway status
```

If teaway reports `disablesleep=1` without an ownership record, an external process or the legacy tool still owns that setting. Resolve it before running `teaway on`.

## What teaway does not import

teaway is a clean implementation with no backward-compatibility layer for legacy state. Specifically:

- It does **not** read `tea-away` state directories
- It does **not** read the `TEA_STATE_DIR` or `TEA_AWAY_STATE_DIR` environment variables
- It does **not** import, rewrite, or delete any legacy state files

If you have those environment variables set in your shell profile, they are ignored by teaway and can be removed at cleanup time.

## Cancelling a leftover legacy shutdown event

If the legacy tool scheduled a `pmset` shutdown using the `tea-away:` owner prefix, that event may still be registered with macOS even after the legacy tool is removed. teaway recognizes the `tea-away:` owner prefix for exact cancellation only, so you can use teaway to clean it up:

```sh
teaway shutdown status
teaway shutdown cancel
```

`teaway shutdown cancel` removes only the exact matching event tuple. It will not touch unrelated Apple wake events or any other scheduled items.

## Cleanup

Once you have confirmed that the handoff is clean — `teaway status` shows no unexpected ownership, and no legacy shutdown event is pending — remove the retired implementation:

1. **Delete the legacy script** and any compiled executable (e.g. the old Swift binary or shell script file)
2. **Remove the legacy state directory** (typically wherever `TEA_STATE_DIR` pointed, or a default location like `~/.local/share/tea-away/`)
3. **Remove any source archives** you downloaded for the legacy implementation
4. **Remove compatibility entrypoints** — any symlinks, wrappers, or shell functions that forwarded to the old tool

After cleanup, you may create a personal alias outside Homebrew if you prefer the shorter name:

```sh
# Add to ~/.zshrc or ~/.bash_profile — do not use brew link or shim for this.
alias tea='teaway'
```

<Warning>
  Do not create a `tea` symlink or shim inside Homebrew's prefix. The `tea` name belongs to a separate, unrelated Homebrew package. Use a plain shell alias in your profile instead.
</Warning>

## Naming note

The `tea-away:` shutdown owner prefix is recognized internally by teaway for exact cancellation during migration and recovery. It is **not** a supported public product name, and it is not exposed as a command or documented interface. Only `teaway` is the supported command.
