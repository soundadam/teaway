---
title: "Schedule and Cancel Delayed Mac Shutdowns with teaway"

The `teaway shutdown` subcommands let you schedule one explicit delayed shutdown, verify that macOS registered the event, and cancel it precisely when your plans change. Every operation is scoped to the single teaway-owned event — teaway never runs broad cancellation commands, never removes unrelated Apple wake or sleep events, and never infers that a workload is finished on its own.

<Warning>
Shutdown scheduling is completely independent of `teaway on` and `teaway off`. Running `teaway off` does **not** cancel a pending shutdown. If you want to cancel a scheduled shutdown, use `teaway shutdown cancel` explicitly.
</Warning>

## teaway shutdown after DURATION

`teaway shutdown after` schedules exactly one shutdown after a bounded explicit duration. teaway resolves the duration to an absolute local deadline, asks macOS to register the power event, verifies that the event appears in the macOS schedule, and prints the full details.

```bash
teaway shutdown after DURATION
```

<ParamField path="DURATION" type="string" required>
  How far in the future to schedule the shutdown. Requires an explicit unit suffix: `m` for minutes, `h` for hours, `d` for days. Examples: `30m`, `2h`, `1d`. Minimum: 10 minutes. Maximum: 7 days.
</ParamField>

### Duration examples

```bash
teaway shutdown after 30m   # 30 minutes from now
teaway shutdown after 2h    # 2 hours from now
teaway shutdown after 1d    # 24 hours from now
```

### Example output

```text
Scheduling shutdown for 2024-07-15 23:15:00 -07:00…
✓ Shutdown scheduled for 2024-07-15 23:15:00 -07:00.
  Host: my-macbook.local
  Cancel it with: teaway shutdown cancel
```

### Constraints

- Only one teaway-owned shutdown may exist at a time. Running `shutdown after` when a teaway event is already pending returns an error — cancel the existing event first.
- The duration must include a unit. A bare number like `30` is not accepted.
- Durations shorter than 10 minutes or longer than 7 days are rejected.
- Scheduling requires administrator authorization (ordinary `sudo` or the registered helper).

## teaway shutdown status

`teaway shutdown status` shows the currently recorded teaway-owned shutdown event and reconciles it against the macOS event schedule.

```bash
teaway shutdown status
```

### Example output — active shutdown

```text
  Shutdown: Scheduled
  Scheduled for: 2024-07-15 23:15:00 -07:00
  Action: teaway:a1b2c3d4
```

### Example output — no active shutdown

```text
  Shutdown: Not scheduled
```

### Stale record reconciliation

`teaway shutdown status` compares the private teaway record against what macOS currently reports in its power event schedule. If macOS no longer lists the recorded event — for example because the Mac rebooted after the deadline already passed — the stale private record is cleared automatically. A subsequent `teaway shutdown after` can then proceed without a conflicting record.

<Note>
`teaway shutdown status` is read-only after reconciliation. If a stale record is cleared, that is a local cleanup of a record that already lapsed — it does not cancel any live macOS event.
</Note>

## teaway shutdown cancel

`teaway shutdown cancel` cancels the exact teaway-owned shutdown event by its recorded tuple. It never runs a broad `pmset` cancellation that could remove unrelated Apple-managed wake or sleep events.

```bash
teaway shutdown cancel
teaway shutdown cancel ACTION_ID
```

<ParamField path="ACTION_ID" type="string">
  Optional. The action ID printed by `shutdown after` or `shutdown status` (for example, `teaway:a1b2c3d4`). When omitted, teaway uses the action ID from its private record. Providing it explicitly is useful for scripted workflows where you want to confirm you are cancelling a specific event.
</ParamField>

### Example

```bash
# Cancel using the stored record
teaway shutdown cancel

# Cancel by explicit action ID
teaway shutdown cancel teaway:a1b2c3d4
```

### Example output

```text
✓ Scheduled shutdown cancelled.
  Action: teaway:a1b2c3d4
```

<Tip>
Find the action ID for the current pending shutdown by running `teaway shutdown status` before cancelling. The action ID is also printed at the time of scheduling by `teaway shutdown after`.
</Tip>

### What cancel does not do

- It does not cancel unrelated Apple scheduled wake, sleep, or restart events.
- It does not affect the awake/sleep setting managed by `teaway on` / `teaway off`.
- It does not cancel events created outside of teaway.
