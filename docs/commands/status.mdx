`teaway status` is your primary diagnostic command. It gives you an immediate, honest snapshot of what your Mac's power configuration looks like right now: whether sleep is disabled, who is responsible for that setting, what power source is active, and whether a teaway-owned shutdown is pending. Run it any time — before enabling awake mode, while a workload is running, or to confirm that `teaway off` restored the original setting.

```bash
teaway status
```

## What status reports

A full status output covers four fields:

| Field | Description |
|---|---|
| **Awake mode** | The current `disablesleep` state and who owns it |
| **Power** | Whether the Mac is running on AC power or battery |
| **Sleep setting** | The live `disablesleep` value read from macOS |
| **Shutdown** | Whether a teaway-owned scheduled shutdown is active |

### Sample output — awake and managed by teaway

```text
Teaway status
  Awake mode: On — managed by teaway
  Power: AC Power
  Sleep setting: disablesleep=1
  Saved setting: disablesleep=0
  Shutdown: Scheduled
  Scheduled for: 2024-07-15 23:15:00 -07:00
  Action: teaway:a1b2c3d4
```

### Sample output — sleep enabled, no active session

```text
Teaway status
  Awake mode: Off
  Power: Battery Power
  Sleep setting: disablesleep=0
  Shutdown: Not scheduled
```

## Awake mode values

<ParamField body="On — managed by teaway" type="string">
  Sleep is disabled (`disablesleep=1`) and teaway holds a valid ownership record. Running `teaway off` will restore the original setting.
</ParamField>

<ParamField body="On — teaway is preserving an existing setting" type="string">
  Sleep was already disabled when `teaway on` ran. teaway holds an ownership record with the same original and expected value. Running `teaway off` will clear the record; the setting itself will remain as it was.
</ParamField>

<ParamField body="Off" type="string">
  Sleep is enabled (`disablesleep=0`). teaway is not active and holds no ownership record.
</ParamField>

<ParamField body="On — controlled outside teaway" type="string">
  Sleep is disabled (`disablesleep=1`) but teaway has no ownership record. Another tool, administrator, or system policy set this value. `teaway off` will not touch it.
</ParamField>

<ParamField body="Needs recovery — run `teaway off`" type="string">
  teaway detected a partially completed transaction — the ownership record was written but the live macOS state is in an intermediate phase. This state is rare and indicates an interrupted `on` or `off` sequence. Run `teaway off` to roll back to the recorded baseline, or `teaway on` to complete a partial enable.
</ParamField>

<ParamField body="Conflict — inspect before making changes" type="string">
  teaway holds an ownership record but the live macOS value does not match what teaway expects. This can occur if an administrator or management profile changed `disablesleep` independently after `teaway on` ran. Inspect the live setting manually before proceeding.
</ParamField>

## Read-only guarantee

<Note>
`teaway status` never requests administrator authorization, never invokes a privileged operation, and never modifies power state or scheduled events. It is safe to run as any user at any time, including inside monitoring scripts or health checks.
</Note>

## Shutdown state

When a teaway-owned shutdown is pending, `status` shows the absolute local deadline (date and time with timezone offset) and the action ID. If no teaway shutdown is scheduled, the field reads `Not scheduled`.

`teaway status` also reconciles the private shutdown record with the macOS event schedule. If macOS no longer reports the event teaway recorded — for example because the machine rebooted and the event lapsed — the stale private record is cleared automatically and `status` will report `Not scheduled` on the next run.

<Tip>
Use `teaway shutdown status` for a dedicated view of shutdown scheduling details, including the action ID needed for exact cancellation. See the [Shutdown reference](/commands/shutdown).
</Tip>
